# Especificación: 002 - Menú principal y páginas iniciales

## 1. Objetivo

Crear el menú principal de WaveCore y las páginas iniciales asociadas, siguiendo la arquitectura feature-driven, el sistema de diseño, la internacionalización y los requisitos responsive del proyecto. La referencia visual es la imagen adjunta a la solicitud.

## 2. Estructura del menú

### Cabecera

- Mostrar el logo de WaveCore y su nombre cuando el menú esté desplegado.
- Incluir el control para alternar entre modo claro y oscuro.
- Incluir un control para plegar y desplegar el menú. Su icono debe comunicar la acción de contraer/expandir; no debe utilizarse una X, ya que no es un botón de cierre.
- En estado plegado, conservar los iconos y proporcionar una forma accesible de identificar cada acción.

### Navegación

- Dejar un pequeño espacio entre la cabecera y el primer elemento.
- Mostrar los elementos de navegación dentro de una región desplazable verticalmente, para permitir añadir más elementos sin desbordar el menú.
- Presentar los elementos en este orden:
  1. **Inicio**
  2. Separador de sección **Finanzas**
  3. **Stack Tecnológico**
  4. **Dashboard**
  5. Separador de sección **Internet of Things**
  6. **IoT**
- Los separadores de sección son etiquetas visuales, no enlaces.
- El elemento activo debe distinguirse visualmente del resto.

### Pie del menú

- Incluir un selector de idioma con los idiomas soportados por el proyecto: Català (`ca`), Español (`es`) e English (`en`).
- Mostrar el nombre del usuario autenticado en Supabase.
- En el caso de una sesión anónima, mostrar el nombre o identificación de invitado que corresponda a esa sesión.

## 3. Páginas y navegación

- **Inicio:** será una feature propia bajo `src/features/home/` y mostrará contenido sencillo de bienvenida o introducción a WaveCore.
- **Stack Tecnológico:** página de prueba accesible desde su elemento de menú; no requiere una feature propia.
- **Dashboard:** página de prueba accesible desde su elemento de menú.
- **IoT:** página de prueba accesible desde su elemento de menú.
- Cada elemento de navegación debe llevar a su página correspondiente y reflejar el estado activo.

## 4. Estado global de autenticación

- El estado de autenticación y la identidad del usuario deben estar disponibles globalmente para que el pie del menú muestre el usuario actual.
- La identidad debe obtenerse de la sesión de Supabase, no de un nombre de usuario codificado en la interfaz.
- El estado global debe mantenerse sincronizado con los cambios de autenticación, incluido el inicio y cierre de sesión.
- La configuración de Supabase debe seguir utilizando `VITE_SUPABASE_URL` y `VITE_SUPABASE_ANON_KEY`; no exponer claves secretas en el cliente.

## 5. Diseño adaptable y accesibilidad

- En escritorio, permitir que el menú lateral se muestre desplegado o plegado.
- En móvil, utilizar una barra superior fija con acceso al menú, logo y control de tema; el menú se abre como un panel lateral tipo drawer con fondo traslúcido.
- Mantener utilizables la navegación, el selector de idioma y el control de tema tanto en escritorio como en móvil.
- La zona desplazable debe limitarse a los elementos de navegación para mantener accesible el pie del menú.
- Utilizar iconos de `lucide-react` y controles con etiquetas accesibles.
- Mantener compatibilidad con los temas claro y oscuro mediante las variables y clases semánticas del sistema de diseño centralizado.

## 6. Internacionalización

- Todo texto estático visible en las páginas y el menú debe estar en los archivos centralizados de traducción para `ca`, `es` y `en`.
- No introducir textos estáticos de interfaz directamente en componentes TSX.
- Los nombres de usuario y demás datos recibidos dinámicamente de Supabase se muestran tal como se reciben.

## 7. Pruebas

- Verificar el renderizado de los elementos, secciones y páginas definidos en esta especificación.
- Verificar que los controles de plegado/despliegue y selección de tema funcionan.
- Verificar que el selector de idioma ofrece los tres idiomas soportados.
- Verificar que el nombre mostrado en el pie corresponde a la sesión de Supabase actual y se actualiza ante cambios de autenticación.
- Mockear Supabase y otros servicios externos en las pruebas unitarias.
