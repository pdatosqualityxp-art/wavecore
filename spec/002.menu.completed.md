# Especificación: 002 - Menú principal y páginas iniciales

## 1. Objetivo

Documentar el menú principal y las páginas iniciales implementados en WaveCore, siguiendo la arquitectura feature-driven, el sistema de diseño, la internacionalización y el comportamiento responsive actual.

## 2. Estructura del menú

### Cabecera

- En escritorio, mostrar el logo de WaveCore y su nombre cuando el menú esté desplegado; en estado plegado, mostrar el logo como control accesible para volver a desplegarlo.
- Incluir el control de tema cuando el menú de escritorio está desplegado.
- Incluir un control de escritorio para plegar o desplegar el menú. En el menú plegado, el logo permite expandirlo.
- En móvil, mostrar una barra superior fija con el botón de apertura del drawer, el logo y nombre de WaveCore, y el control de tema.
- El drawer móvil incluye un control para cerrarlo y se cierra también al seleccionar una ruta, pulsar el fondo traslúcido o usar Escape.

### Navegación

- Presentar los elementos dentro de una región desplazable verticalmente; el pie permanece fuera de esa región.
- Mostrar los elementos principales en este orden:
  1. **Inicio** (`/`)
  2. Separador de sección **Finanzas**
  3. **Stack Tecnológico** (`/stack`)
  4. **Dashboard** (`/dashboard`)
  5. Separador de sección **Internet of Things**
  6. **IoT** (`/iot`)
  7. Separador de sección **Pruebas**
  8. **Prueba 1** a **Prueba 15** (`/demo-1` a `/demo-15`)
- Los separadores son etiquetas visuales, no enlaces.
- La ruta actual se distingue visualmente como elemento activo.
- En escritorio plegado, se ocultan las etiquetas, se mantienen los iconos y cada enlace conserva un nombre accesible y un `title`.
- En móvil, la barra lateral conserva su anchura desplegada y muestra las etiquetas, independientemente del estado plegado de escritorio.

## 3. Pie del menú e identidad

- Incluir un selector de idioma para Català (`ca`), Español (`es`) e English (`en`). El selector ofrece esas tres opciones y permite elegirlas mediante teclado.
- Mostrar una tarjeta de cuenta que abre un menú con la identidad del usuario y la acción para cerrar sesión.
- Para usuarios autenticados no anónimos, obtener el perfil de `z_users` por el identificador de usuario de Supabase. Mostrar `display_name` si existe; de lo contrario, usar el correo del perfil y después el correo de la sesión. Mientras se carga el perfil o cuando no está disponible, mostrar el estado correspondiente.
- Para sesiones anónimas, mostrar las etiquetas traducidas **User Guest** y **WaveCore Guest**; no se muestra un identificador único de esa sesión.
- El texto **Invitado** es el fallback cuando no hay usuario, aunque la ruta principal muestra la pantalla de inicio de sesión en ese estado.
- La acción de cerrar sesión cierra el menú de cuenta y vuelve a `/` si tiene éxito. Si falla, mantiene el menú abierto y presenta un mensaje de error.
- Mostrar la versión **Ver 1.1** al pie cuando el menú está desplegado. Actualmente este texto está escrito directamente en el componente y no utiliza una clave de traducción. En escritorio plegado se oculta.

## 4. Páginas y rutas

- **Inicio** (`/`): feature en `src/features/home/` con contenido introductorio de WaveCore.
- **Stack Tecnológico** (`/stack`), **Dashboard** (`/dashboard`) e **IoT** (`/iot`): páginas de prueba renderizadas por un componente compartido.
- **Pruebas** (`/demo-1` a `/demo-15`): enlaces y páginas de prueba renderizados mediante datos compartidos.
- Las páginas principales y de prueba se muestran dentro de la estructura de `AppShell` y cada enlace refleja la ruta activa.
- Mientras se comprueba la sesión se muestra un estado de carga. Si no hay sesión, `/` muestra el inicio de sesión; el menú principal se muestra con una sesión autenticada.
- `/test_login` es una ruta independiente para explorar Supabase y no forma parte de la navegación del menú.

## 5. Estado global de autenticación y tema

- El estado global de autenticación escucha los cambios de sesión de Supabase y carga el perfil del usuario desde `z_users`.
- La configuración de Supabase utiliza `VITE_SUPABASE_URL` y `VITE_SUPABASE_ANON_KEY`; no se exponen claves secretas en el cliente.
- El tema admite modo claro y oscuro, se aplica mediante la clase `dark` del elemento raíz y se persiste en `localStorage` bajo `wavecore-theme`.
- El tema inicial actual es oscuro; al cambiarlo, la interfaz se actualiza inmediatamente.
- En escritorio plegado no se muestra el botón de tema en la barra lateral. En móvil, el control permanece disponible en la barra superior.

## 6. Diseño, internacionalización y accesibilidad

- Utilizar las clases semánticas del sistema centralizado de diseño para superficies, colores, bordes y estados; Tailwind se utiliza para layout y responsive.
- Usar iconos de `lucide-react` y controles con etiquetas accesibles.
- Todo texto estático de la interfaz debe estar centralizado en los archivos de traducción de `ca`, `es` y `en`, salvo la versión **Ver 1.1**, que actualmente es una excepción implementada como texto literal.
- Los valores dinámicos recibidos desde Supabase se muestran según el comportamiento descrito en la sección de identidad.
- El control de idioma permite navegación por teclado y cierra el selector al elegir una opción, pulsar fuera o usar Escape.

## 7. Pruebas

- Verificar los enlaces, etiquetas de sección, rutas activas y estados de idioma del menú.
- Verificar el plegado y despliegue de escritorio, el drawer móvil y los controles de tema.
- Verificar las opciones `ca`, `es` y `en`.
- Mockear Supabase en las pruebas unitarias.
- Verificar que el pie muestra los datos disponibles de `z_users`, los fallbacks, la identidad fija para sesiones anónimas y los cambios de sesión.
- Verificar el cierre de sesión tanto cuando tiene éxito como cuando falla.
